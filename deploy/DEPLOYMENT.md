# Deploy YelloBot (Vercel + Render + Qdrant Cloud)

This guide assumes you have **no prior deployment experience**. Follow the steps in order.  
Estimated time: **45–90 minutes** (mostly waiting for builds).

You will create accounts on 4 services:

| Service | What it hosts |
|---------|----------------|
| [Groq](https://console.groq.com) | AI chat (API key) |
| [Qdrant Cloud](https://cloud.qdrant.io) | Document search vectors |
| [Render](https://render.com) | Backend API + database + Redis + file storage |
| [Vercel](https://vercel.com) | React frontend |

Your app repo: `https://github.com/v-i-s-h-a-l-l/ai-chat-platform`

---

## Before you start

1. Push this repo to GitHub (if not already on `main`).
2. Have a Groq API key ready ([console.groq.com](https://console.groq.com)).
3. Use Chrome/Edge — Render and Vercel login with GitHub.
4. Render **Starter** plans for Postgres, Redis, and disk are **paid** (~$21/mo total) — see [Cost estimate](#cost-estimate).

---

## Part 1 — Qdrant Cloud (5 min)

1. Sign up at [cloud.qdrant.io](https://cloud.qdrant.io).
2. **Create cluster** → choose **Free** tier → pick a region close to you.
3. When ready, copy:
   - **Cluster URL** (looks like `https://xxxxxxxx.us-east-1-0.aws.cloud.qdrant.io`)
   - **API Key**
4. Save these in a notes file — you will paste them into Render later.

---

## Part 2 — Render backend (30–45 min)

Render deploys from a **Blueprint** in this repo: `deploy/render.yaml`.  
It creates the API, Postgres, Redis, and a **1 GB disk** for uploaded PDFs (all in one step).

### 2.1 Create the Blueprint

1. Go to [dashboard.render.com](https://dashboard.render.com) → **Sign in with GitHub**.
2. Click **New +** → **Blueprint**.
3. Connect repository **`v-i-s-h-a-l-l/ai-chat-platform`**.
4. Set **Blueprint Path** to: `deploy/render.yaml`
5. Click **Apply** and confirm the resources listed.

The blueprint creates:

| Resource | Purpose |
|----------|---------|
| `yellobot-api` | Web service (API + ingestion worker in one container) |
| `yellobot-postgres` | PostgreSQL — auto-wires `DATABASE_URL` |
| `yellobot-redis` | Redis — auto-wires `REDIS_URL` |
| Disk at `/app/storage` | Persistent uploaded PDFs (1 GB) |

Docker image: `backend/Dockerfile.production` (API + worker combined so they share the disk).

### 2.2 Set required secrets

During Blueprint setup, Render prompts for variables marked `sync: false`. Enter:

| Variable | Value |
|----------|-------|
| `GROQ_API_KEY` | Your Groq API key |
| `HUGGINGFACE_API_KEY` | Token from [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens) |
| `QDRANT_URL` | Qdrant Cloud cluster URL |
| `QDRANT_API_KEY` | Qdrant Cloud API key |
| `CORS_ORIGINS` | `https://placeholder.vercel.app` (update after Part 3) |

`SECRET_KEY` and `METRICS_TOKEN` are auto-generated by the blueprint.

You can also set or edit these later: **Dashboard** → **yellobot-api** → **Environment**.

### 2.3 Set environment variables (reference)

If you need to add or verify variables manually, use **yellobot-api** → **Environment**:

```env
ENVIRONMENT=production
SECRET_KEY=PASTE_RANDOM_STRING_1
GROQ_API_KEY=your_groq_key
QDRANT_URL=https://your-cluster.cloud.qdrant.io
QDRANT_API_KEY=your_qdrant_api_key
CORS_ORIGINS=https://placeholder.vercel.app
COOKIE_SECURE=true
COOKIE_SAMESITE=none
RATE_LIMIT_USE_REDIS=true
INGESTION_INLINE_FALLBACK=false
RAG_ENABLED=true
METRICS_ENABLED=true
METRICS_TOKEN=PASTE_RANDOM_STRING_2
DOCUMENT_STORAGE_PATH=/app/storage/documents
INGESTION_MAX_JOBS=2

EMBEDDING_PROVIDER=huggingface
HUGGINGFACE_API_KEY=your_huggingface_token
HUGGINGFACE_API_URL=https://router.huggingface.co/hf-inference
HUGGINGFACE_EMBEDDING_BATCH_SIZE=16
RERANK_ENABLED=false
EMBEDDING_MODEL=BAAI/bge-base-en-v1.5
EMBEDDING_DIMENSION=768
```

Generate random strings (PowerShell):

```powershell
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }) -as [byte[]])
```

Run twice for `SECRET_KEY` and `METRICS_TOKEN`, or use:

```powershell
.\deploy\generate-secrets.ps1
```

**Auto-filled by the blueprint (do not paste manually):**

- `DATABASE_URL` ← from `yellobot-postgres`
- `REDIS_URL` ← from `yellobot-redis`

**Important:** Leave `CORS_ORIGINS` as a placeholder for now — update it after Vercel (Part 3).

### 2.4 Deploy

1. Render builds and deploys after Blueprint apply (or on each GitHub push).
2. First deploy takes **10–20 minutes** (installs PyTorch + embedding models).
3. Open **yellobot-api** → copy your public URL, e.g. `https://yellobot-api.onrender.com`.
4. Test: open `https://YOUR-RENDER-URL/health` — should show `"status":"healthy"` (may be `"degraded"` briefly until Qdrant is reachable).

Database migrations run automatically on startup via `backend/scripts/start_production.sh`.  
To run manually: **yellobot-api** → **Shell** → `alembic upgrade head`.

## Part 3 — Vercel frontend (10 min)

1. Go to [vercel.com](https://vercel.com) → **Login with GitHub**.
2. **Add New…** → **Project** → import **`ai-chat-platform`**.
3. Configure:
   - **Framework Preset**: Vite
   - **Root Directory**: `frontend`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. **Environment Variables**:

   | Name | Value |
   |------|-------|
   | `VITE_API_URL` | Your Render URL from Part 2.4 (no trailing slash) |

5. Click **Deploy**.
6. Copy your Vercel URL, e.g. `https://ai-chat-platform.vercel.app`.

### 3.1 Finish cross-origin auth

Go back to **Render** → **yellobot-api** → **Environment**:

- Update `CORS_ORIGINS` to your **exact Vercel URL** (e.g. `https://ai-chat-platform.vercel.app`).
- Render redeploys automatically.

---

## Part 4 — Verify everything works

Open your **Vercel URL** in the browser:

1. **Register** a new account → should succeed (no CORS errors in DevTools → Console).
2. **Refresh the page** → you should stay logged in.
3. Create a **project**.
4. **Upload a PDF** → wait until status shows **Ready** (may take 1–3 min on first run while models load).
5. Ask: **"What is this document about?"** → answer should come from the document.

If upload stays on "Processing" forever:

- Render → **yellobot-api** → **Logs** → check worker errors (Redis, Qdrant, or out-of-memory).
- Ensure **disk** is attached at `/app/storage` (Blueprint creates this automatically).
- Ensure `REDIS_URL`, `QDRANT_URL`, and `QDRANT_API_KEY` are set.

## Troubleshooting

### Login fails / 401 on every request

- `CORS_ORIGINS` must exactly match your Vercel URL.
- `COOKIE_SAMESITE=none` and `COOKIE_SECURE=true` must both be set.

### "I cannot access uploaded documents"

- Check `/health` — `qdrant` and `redis` should be `true`.
- Confirm document shows **Ready** with chunk count.
- Check Render logs for RAG retrieval lines.

### Build runs out of memory

- Render → **yellobot-api** → confirm `EMBEDDING_PROVIDER=huggingface` and `RERANK_ENABLED=false` (no local PyTorch).
- Increase instance type if needed (512MB–1GB is usually enough with HF API embeddings).

### Embeddings fail / ingestion errors mentioning Hugging Face

- Set `HUGGINGFACE_API_KEY` (token from [huggingface.co/settings/tokens](https://huggingface.co/settings/tokens)).
- Keep `EMBEDDING_MODEL=BAAI/bge-base-en-v1.5` (must match `EMBEDDING_DIMENSION=768`).
- Free HF tier may return HTTP 503 while the model loads — retries are built in; wait and retry upload.

### Health check fails on deploy

- First boot runs DB migrations + model download — allow up to 10 minutes.
- Check **Logs** for Alembic or PyTorch install errors.

### Blueprint apply fails

- Confirm **Blueprint Path** is `deploy/render.yaml`.
- Ensure the repo is pushed to GitHub with the latest `deploy/render.yaml`.

### Docker build error: `backend/backend: no such file or directory`

Render joins **Root Directory** with **Docker Context**. If both point at `backend`, you get `backend/backend`.

In `deploy/render.yaml` use:

```yaml
rootDir: backend
dockerfilePath: ./Dockerfile.production
dockerContext: .
```

Or in Render Dashboard: Root Directory = `backend`, Dockerfile Path = `Dockerfile.production`, Docker Context = `.`

### Frontend calls localhost instead of Render API

- Set `VITE_API_URL` in Vercel environment variables (no trailing slash).
- Redeploy Vercel after changing — Vite bakes env vars at build time.
- Repo includes `frontend/.env.production` as a fallback for production builds.

### CORS / cookie auth fails on custom domain

- Set `CORS_ORIGINS=https://yellobot.online,https://www.yellobot.online` (both if you use www).
- No trailing slashes — backend strips them automatically.
- `COOKIE_SECURE=true` and `COOKIE_SAMESITE=none` must both be set.
